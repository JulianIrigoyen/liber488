- **Everything said to DJINN as Julian becomes a Julian-owned fact the next day** —
  including `djinn-ask`/`djinn-chat` briefings and test prompts. Interim status became
  stale facts within hours. Brief with statements that stay true; retire the rest with
  `retire-facts.mjs`.
- DJINN runs as `djinn-worker` (uid 994) and **cannot read `/root`**. Durable awareness =
  ship it in the release (`CLAUDE.md`, `memory/*.md`) or write a note into `/root/brain/`
  (the live vault; `brain-weave` links it nightly). `/root/djinn-vault` is the stale wiki.
- Supabase migration 0008 accepts fact provenance only as `kind:'runtime_inputs'` with
  non-empty `inputIds`; the historical import creates real `inputs` rows, so pointing at
  them is honest — no migration needed.
- Live DM inputs are thread-scoped; `scopeRoom` collapses to `team:channel:user`.
- The release keeps **851 MB of `node_modules`** — never ship it; git does not track it.
- Backgrounded scripts keep `ssh djinn` sessions on the one master; `sshd MaxSessions`
  is 10. `ssh -O exit djinn` resets (kills anything mid-transfer). Never `pkill` by a
  pattern that can match your own shell.
- `.env.*` backup files in the release are not gitignored — never `git add -A` a copy.
- `djinn-ask.mjs` treats *any* argument as a question (`--help` posted to Slack).
- `gh` is on HTTPS as `JulianIrigoyen`; both SSH keys authenticate as that account only
  via `id_ed25519` — `id_ed25519_supersolid` is registered nowhere, by decision.
- macOS has no `timeout`; the harness blocks foreground `sleep`.
