## 1. "Could you reproduce this website?"

The site at `sunny-harbor-32.s2.seeiousercontent.com` was pulled down and analysed: 11
static pages, one 12 KB stylesheet, a 7 KB shared script with a procedural seal
generator, four page scripts, ~87 KB of hexagram/spirit/lexicon data, 14 hand-drawn SVG
plates. No framework, no build, no backend. Verdict: the shell is hours; the corpus and the
plates are the real cost. At this point I did not know the site was ours.

## 2. Liber Daemonicum — the twist (rejected)

Asked for "a twist based on all you know about me", I built a grimoire of the agent stack:
a daemon roster with a caution column, sixty-four system states read as an oracle (six
services × up/down), a tree from intent to metal, a sigil bench that draws a name's own
hash. Published as an artifact. Verdict from Julian: "incredibly uglier and the symbols
are ugly — but the I Ching idea is dope." Kept under `experiments/liber-daemonicum/` for
the one idea that survived: a hexagram is six binary lines and so is a health check.

## 3. The Oracle of Changes — the real thing, standalone

Rebuilt as a genuine consultation tool, published as a second artifact:
- **Casting by the querent's own gesture.** Julian's objection was exact: a button on an
  RNG removes the querent from the causal chain. So the entropy is the hand's motion,
  extracted through SHA-256 so the coin/yarrow distributions hold exactly. Six separate
  throws. Question required, locked on the first throw.
- **The full corpus:** all 64 hexagrams and all 384 changing-line texts, original
  interpretive writing (not translations); coins and yarrow with their genuinely different
  probabilities; changing lines → relating hexagram; a "which lines govern" rubric;
  repeat-question detection quoting the tradition's own warning; a local journal.
- Verified headless: a full six-throw cast, changing lines, relating hexagram, journal.

Julian then used it for a real reading. Analysing it — and being told plainly that the
first analysis was unreadable — produced the rules that now govern the AI interpreter:
plain English above all; place the querent in the figure; give both readings of an
ambiguous line and state the unflattering one; the second hexagram is not a prediction.
The reading itself is his and is not recorded here.

## 4. API-first

Decisions: no droplet for this; API first so there is a web app; native later; I Ching
first, then tarot, natal chart, news, all AI-boosted; AI requires login and is rate-limited.

Built `api/`: TypeScript + Hono (runtime-portable; only the D1 calls are
Cloudflare-specific). Magic-link auth → 30-day JWT; per-day AI quota by tier (free 3,
adept 30, magus 200), **charged before the model call** so a crash is not a free retry;
`POST /v1/oracles/iching/resolve` so the **server decides what a cast means** (no spoofing
a hexagram from a console) while casting itself never leaves the device; streaming
interpretation on `claude-opus-5` with adaptive thinking and server-side fallback;
saved readings. The interpreter prompt encodes the rules from §3.

Typecheck caught two real bugs invisible to every earlier check: an SDK pin from memory
(`^0.68.0`; the real current version was `0.126.0`, which silently loses adaptive thinking)
and Hono's `verify()` needing three arguments. Dependencies installed (10 minutes on this
link), `tsc --noEmit` clean. The API has run locally (health, resolve, auth gating, quota
verified with curl) but **never against the live model** — no Anthropic key on this Mac.

## 7. "Interpret with AI" through DJINN, for now

With no key on this machine, the AI button was wired through DJINN: `dev/djinn-bridge.mjs`
shells out to `djinn-ask.mjs` on the droplet. It works — 111–123 s per reading, and on a
real cast the interpretation followed the rules, including taking the unflattering reading.
Two facts learned the hard way and fixed: every call posts to Julian's private DM (fixed
by creating one thread and replying inside it — `djinn-ask` only posts a new parent when
not given `--thread`); and DJINN accepts the prompt as a bare message only if told to drop
its company-agent framing. `dev/djinn-chat.mjs` gives genuine multi-turn (`--thread` +
`--carry`), verified.

WhatsApp for DJINN was designed, not built: inbound is easy (`store.capture` is not
Slack-specific); outbound is Slack-shaped, so either a relay or a delivery-layer change
that is Astra's to write. Blocked on provider, a public webhook, and an allowlist decision.
